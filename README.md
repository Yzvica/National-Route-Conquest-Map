# National-Route-Conquest-Map(国道制覇マップ)

自分の走行ログを読み込んで、日本の国道をどれだけ走ったか(制覇率)を地図で確認するウェブアプリです。

- 走行ログ(gbowl の CSV / GPX)は「走行ログを読み込む」で選ぶか、画面にドラッグ＆ドロップして読み込みます(複数可)
- 画面で読み込んだログの判定はブラウザの中で行い、MiniPC には判定結果(区間ごとの割合と、初めて/最後に通った日)を保存します。
  読み込んだログ自体も MiniPC の `data\logs` に圧縮して残し、「保存したログで判定し直す」でまとめて判定し直せます。
  判定し直しは MiniPC のサーバーで行うので、始めたあとは画面を閉じても続きます(開いていれば進み具合が出ます)。
  同じログ(名前も中身も同じもの)をもう一度読み込んでも、二重には保存しません。前に重複して保存されたものは、サーバーを立ち上げたときに `data\logs\duplicates` に移します
  判定し直すと通った区間の記録は作り直され(前の判定の誤りは消えます)、前の記録は `data\backup` に控えが残ります
- ほかのツールからログを自動で送ることもできます(gbowl-log-formatter の `RunAll.bat` / `SendToMap.bat`)。
  `POST /api/inbox?name=<ファイル名>` に走行ログをそのまま本文で送ると MiniPC に保存され、
  MiniPC のサーバーがそのまま判定して記録に足します(地図を開いておく必要はありません)。
  同じログを何度送っても二重には取り込みません。まだ判定していないログは `data\logs\pending.json` に残ります
- サーバーでの判定は、別のスレッド(`server/build/judgeWorker.js`、`npm run build` で `src/judgeWorker.ts` から作る)で道路データを読んで行います。
  道路データを読むと数百MBのメモリを使うので、判定が終わって3分たつと手放します。
  `server/build` がない(ビルドしていない)ときは、前と同じくブラウザで判定します
  ```sh
  curl --data-binary @"2026-11-01 09_00_00 (30m) DriverA.csv" "http://<MiniPC>:8080/api/inbox?name=2026-11-01%2009_00_00%20(30m)%20DriverA.csv"
  ```
- 「高速道路」タブでは、高速自動車国道 / 都市高速 / 自動車専用道路 / 有料道路の制覇率を道路名ごとに出します
- 国道ごと、種別ごと(現道 / バイパス / 点線国道 / 海上区間 / 重複区間 / 旧道)、総合の制覇率を距離ベースで出します
- 総合制覇率では重複区間を1回だけ数え、国道ごとの制覇率ではそれぞれの国道に数えます
- 点線国道は参考データとして別に出し、総合・国道ごとの制覇率や実績には入れません。
  車で走るログでは判定しにくく(関門トンネルの人道を通ったことになるなど)、ログの判定は使わずに
  「種別ごと」の内訳や国道の詳細にあるチェックボックスで、国道ごとに走ったと自己申告します
- 旧道(バイパスができて国道でなくなった旧ルートなど)も別枠で出し、総合・国道ごとの制覇率には入れません。
  こちらは車で走れる道なので、ログで判定します。地図では細い破線で描き、旧道の走行距離の実績があります
- パネル上部のレベルの枠から、ゲーム要素の画面を開けます(`src/game.ts`)
  - 実績: 走行距離・制覇率・制覇した路線数・名所・点線国道・海上区間・トンネル・都道府県など
  - レベル・称号: 経験値(国道 1km = 1、高速 1km = 0.5、国道の制覇 1本 = 30、高速の制覇 1路線 = 15、実績 1つ = 50)で上がります。
    いちばん制覇率の高い地方で「関東の主」などの称号も付きます
  - おすすめ: あと少しで制覇できる路線と、よく走るあたりから近い未踏路線
  - 振り返り: ログ上の走行距離、年ごとのまとめ、月ごとの走行距離・開拓距離、制覇率の推移、制覇のタイムライン。
    ログ上の走行距離は読み込んだときに計算します。前から保存してあるログは「保存したログで判定し直す」で数えられます
    MiniPC に保存してある走行ログの一覧(日付・距離)もあり、名前を押すとその走行の軌跡を地図に出します。
    日付と距離はログを読み込んだときに `data\logs\meta.json` に残します。前から保存してあるログは、押して開くか「保存したログで判定し直す」で付きます
  - 都道府県: 都道府県・地方ごとの制覇率と、地図の色分け
  - 路線は走行率 95% 以上で「制覇」とします(`CONQUER_RATIO`)

## 使い方(手元で動かす)

```sh
npm install
python3 scripts/build_routes.py --ref 1 --ref 20   # 国道データを作る(全国なら --ref なし。数分かかります)
npm run dev
```

## 判定のしくみ

| 項目 | 内容 |
| --- | --- |
| 判定の単位 | OSM の道路を約200mごとに区切った「区間」 |
| 通過判定 | 区間を20mおきに見て、ログから30m以内を、道路と同じ向き(差が45度以内。上り下りは問わない)に進んでいれば通過。8割以上通れば100%、それ未満は割合で記録 |
| 交差 | 向きを比べるので、立体交差や交差点で横切っただけの道路(国道の上を通る高速道路など)は走ったことにならない。止まっていて向きが分からないログの点は使わない |
| ログの途切れ | 点と点が2km以内で、速度が時速200km以下なら、間を直線で補間 |
| トンネル | 中の GPS は見ず、両方の坑口の80m以内を短い時間差で通っていれば、トンネル全体を制覇扱い |
| 高架の高速道路と下の国道 | 先にログの各点が高速道路の上か下の道かを決め、高速道路は上の点だけ、国道・都道府県道は下の点だけで判定する(`src/layers.ts`)。下の表のとおり |

高架の高速道路と、その下を並んで走る国道は GPS の位置だけでは区別できないので、ログの前後の流れで決めます。

- 近くに高速道路しかなければ高速道路の上、高速道路がなければ下の道。
  路線に数えない本線(「〜インター線」などの名前のもの)と、IC・JCT のランプも「近くの高速道路」とみなす
- 両方が並んでいるところは、その前のまま。乗り換えられるのは高速道路に出入りできる場所(ランプが本線につながる点・本線の端)の近くだけ
- IC のランプを進む向きに通ったら、入口なら高速道路に乗った、出口なら降りたとする。
  道の真ん中から上がるランプのように下の道と重なっているランプは決め手にならないので、そのあと信号で止まったかで決める
  - 本線側の端では、出入りできる範囲(150m の1.5倍)を抜けるまでずっと乗った/降りたとする(出入りできる場所の近くで一瞬だけ乗り換えて戻ったことにしない)
  - 出口のランプは、本線から30m以上離れた部分を通ったかで確かめる(本線に沿って分かれるランプでは、本線を走り続けただけで通ったように見えるため)
  - 出口のランプを降りてすぐ(600m 以内)、止まらずに入口のランプを上ったら、料金所・JCT・PA の通り抜けとみなして、どちらも使わない
- 20秒以上止まったら下の道(信号)、時速100kmを超えたら高速道路に寄せる(渋滞もあるので弱め)
- 高速道路と下の道が並ぶ所を、前後1km以上減速せずに(時速10km以上で)走ったら、少しずつ高速道路に寄せる。
  並んでいる下の道には信号があることが多いため(時速60〜80kmの高架は、時速100kmの手がかりだけでは見分けられない)
- 高度は使わない(スマホや GoPro の GPS の高度は誤差が大きいため)
- 国道の自動車専用道路のように、国道と高速道路の両方のデータにある同じ道は、どちらとしても数える
- ランプと出入りできる場所は高速道路データ(`expressways.json` の `ramps`・`access`、路線に数えない本線は `uncounted`、JCT のランプは `jct`)に入っています。古いデータにはないので、
  そのときは並んでいる区間の前後の流れと速度・停止だけで決めます(高速道路データを作り直すと精度が上がります)

数値は `src/matcher.ts` の `DEFAULT_OPTIONS` で変えられます。

## 国道データ

OpenStreetMap の `network=JP:national` の路線リレーションから作ります。
データは大きいのでリポジトリには入れず、Actions の「国道データを更新」でリリース `route-data` に置き、公開時に取り込みます。
Actions では [Geofabrik](https://download.geofabrik.de/asia/japan.html) の日本全体のファイルから抽出します(`scripts/extract_pbf.py`)。
Overpass API から直接取ることもできますが、混雑で断られることがあります。

画面では、国道・高速道路のデータを分けて読みます(`scripts/split_data.mjs`。`npm run build` の最初に `public/data/split/` を作ります)。
区間の番号・長さ・両端の点などの一覧(国道は約18MB。gzip で約4MB)を先に読んで制覇率や引いた縮尺の線を出し、
区間の途中の点は 0.5 度ごとのマスに分けて、拡大した場所やログが通った場所の分だけあとから読みます。
`split/` がないとき(`npm run dev` で作り忘れたときなど)は、前と同じく `routes.json` を丸ごと読みます。
MiniPC のサーバーでの判定は、今までどおり `routes.json` をそのまま使います。

種別の判定方法:

- 海上区間: `route=ferry`
- 道路でない線(`highway` のないもの、工事中・計画中・廃道)は、国道のリレーションに入っていても除きます
- 点線国道: `highway=path / track / footway / steps` など、車道でない区間。
  ただし車道のすぐ脇を通る歩道・自転車道・人道トンネル(関門トンネルなど)は点線国道ではないので除きます(`drop_sidewalks`)
- バイパス: 名前に「バイパス」を含む区間
- 重複区間: 複数の国道リレーションに含まれる区間
- 旧道: 国道リレーションに入っていない道路のうち、次のもの(`scripts/build_old_roads.py`)。歩道・小道などは除きます
  - `old_ref` が国道の番号(「国道1号」。数字だけの「1」は、県道の旧番号のこともあるので `old_highway=trunk` があるものだけ)
  - 名前(`name`・`old_name`・`alt_name` など)が「旧国道1号」「旧1号」「国道1号旧道」のように番号付き
  - 名前が「旧道」「旧国道」だけで番号のないもの(「県道12号旧道」のような県道の旧道は拾わない)。つながっている道ごとにまとめ、両端の近く(150m以内)を通る国道の旧道とする
  - どれも、つながっている道のまとまりのどこかが同じ番号の今の国道から約1〜2km以内にあるものだけ(昔の番号の付け方の「旧国道N号」などを除くため)

  旧道だけ付け直したいときは、Actions を target = `old` で実行します

## 高速道路データ

同じ Actions で `expressways.json` も作ります(`scripts/build_expressways.py`)。

- 対象: `highway=motorway`(本線のみ。IC・JCT のランプ `motorway_link` は数えない)、`motorroad=yes` の一般道、`toll=yes` の一般道
- 路線: OSM の道路名ごと(「東北中央自動車道;相馬福島道路」のような併記は最初の名前)
- 種別: 首都高速・阪神高速などは都市高速、名前に「自動車道」「高速道路」を含むものは高速自動車国道、ほかの本線と `motorroad=yes` は自動車専用道路、残りの `toll=yes` は有料道路。
  法律上の区分(高速自動車国道か一般国道の自動車専用道路か)とは一部ずれます
- 上下線: 別の線で描かれているところは反対向きの区間を組にし、どちらかを走れば制覇、長さは道路1本分で数えます
- ランプ: IC のランプ(`motorway_link`・自動車専用道路の `trunk_link`)は制覇率には数えませんが、
  高架の高速道路と下の国道を見分けるために、向き付きの線(`ramps`、入口 `in` / 出口 `out`)と出入りできる場所(`access`)を入れます。
  JCT のランプ(本線どうしをつなぐもの)の線は `jct` に入れます
- 路線に数えない本線: 「〜インター線」「〜ランプ」「JCT」などの名前の `highway=motorway` や、短い切れ端は路線に数えませんが、
  `uncounted` に線を入れ、ランプの判定では本線として扱います(松山外環状道路インター線のように、高架の本線そのものがこの名前のことがあるため)

## 都道府県

Actions で各区間に都道府県(`pref`)を付け、地図の色分け用の `prefectures.json` も作ります(`scripts/add_prefectures.py`)。
都道府県の境界は OSM の行政界(`admin_level=4`)です。県別の距離は、その都道府県の中にある分だけを数えます。
都道府県の境をまたぐ区間は5mおきの点で調べ、それぞれの都道府県にある割合(`prefs`)を付けて距離を分けます。
海上区間など、どこにも入らない区間は一番近い都道府県にします。
道路データを作り直さずに都道府県だけ付けたいときは、Actions を target = `pref` で実行します。

## MiniPC(Windows 11)で動かして LAN から使う

MiniPC でサーバーを動かし、LAN 内の PC やスマホのブラウザから開きます。
走行記録は MiniPC の `data\record.json` に保存されるので、どの端末から見ても同じ記録になります。

必要なもの: [Node.js](https://nodejs.org/) 22 以上、[Git](https://git-scm.com/)、[GitHub CLI](https://cli.github.com/)

```powershell
git clone https://github.com/Yzvica/National-Route-Conquest-Map.git
cd National-Route-Conquest-Map
gh auth login                                                    # 初回だけ
powershell -ExecutionPolicy Bypass -File scripts\update.ps1      # 国道データの取得とビルド
npm run serve                                                    # http://<MiniPCのIPアドレス>:8080 で開ける
```

起動時に自動で立ち上げるには、管理者の PowerShell で次を一度だけ実行します(タスクスケジューラへの登録と、ファイアウォールで 8080 番ポートを家庭内ネットワークに開放します)。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1
```

- サーバーはタスク `KokudoMap`(ログオンしていなくても動く S4U)の中の `scripts\run-server.ps1` のループが動かします。1回分の起動と見守りは `scripts\server-once.ps1` で、起動のたびに読み直すので、ループを止めずに新しくなります
- **自動更新**: あわせてタスク `KokudoMapUpdate` も登録され、5分ごとに GitHub の main と国道データ(リリース route-data)を調べ、新しいものがあれば `scripts\update.ps1` で取り込んでサーバーを再起動します。PR をマージすれば、遅くとも5分ほどで取り込みが始まり、ビルドと再起動まで数分で反映されます。調べるだけなら GitHub に2回問い合わせるだけで、国道データも変わっていなければ取り直しません。git / gh のログイン情報を使うので、MiniPC にログオンしている間だけ動きます。記録は `data\update.log`。管理者なしで `scripts\install-autoupdate.ps1` だけ登録し直すこともでき、`-Remove` でやめられます
- 手で取り込むときは、フォルダ直下の `update.bat` をダブルクリックします(管理者は不要)。国道データは前回から変わっていなければ取り直しません
- 再起動だけしたいときは `powershell -ExecutionPolicy Bypass -File scripts\restart-server.ps1`。`data\restart.request` を置いてタスクの中のループに頼むので、管理者でなくても(Remote Control からでも)再起動できます
  国道データなどはリリースから `scripts/download_release.mjs` で取ります。回線によって GitHub のファイル配信が極端に遅いことがあるので、256KBずつに分けて同時に取ります
- サーバーが落ちても10秒後に自動で立ち上げ直します。落ちた記録とエラーは `data\server.log` に残ります
- `data\record.json` をコピーしておけばバックアップになります。画面の「記録を書き出す」でも保存できます
- `npm run dev` で開いたときなど、サーバーがない場合はブラウザの中に保存します

地図の背景には[地理院タイル](https://maps.gsi.go.jp/development/ichiran.html)、道路データには © OpenStreetMap contributors を使っています。

## 走ったときの天気

- iPhone の走行ロガーの生データ(`meta.json` は最後に届く)を受け取ると、MiniPC が走った時刻・場所の天気を [Open-Meteo](https://open-meteo.com/)(無料・キー不要)から取り、走行フォルダに `weather.json` を書きます。飛行機の記録は取りません
- 最初と最後、その間は30分か30kmごとの地点(最大48)で、天気・気温・体感温度・湿度・1時間の降水量・雲量・海面気圧・風(向き・速さ・瞬間)・昼夜を取ります。まとめは「雨か雪に一度でも当たればそれ、降っていなければいちばん多かった天気」
- 値は気象モデルの解析値で、観測所の実測ではありません。約3か月より前の走行は過去データ(ERA5、1940年〜)で取ります
- インターネットにつながらず取れなかった走行は `data\weather_pending.json` に残し、30分ごとに取り直します(14日であきらめる)。サーバーを起動したときも、天気のない走行フォルダ(`old`・`trips` も)を探して取ります
- 地図の「ログ」タブで、一覧にアイコンと気温、詳細に天気が出ます。iPhone 以外のログ(GBowl・GoPro)は、開いたときにブラウザが軌跡の点を送り、`<RAW_LOG_DIR>\weather\<ログ名>.json` に残します
- API: `GET /api/rawlog?session=&file=weather.json`(アプリ用)、`GET|POST /api/rawlog/weather?session=[&kind=trip]`(POST は取り直し)、`GET|POST /api/logs/<id>/weather`
- 環境変数 `WEATHER=off` で取らないようにできます

## 背景の地図と現在位置

- 地図右下の欄で背景を「淡色地図 / 白地図 / 標準地図 / 写真」(地理院タイル)から選べます。選んだものはブラウザに覚えます。白地図は ZL5〜14 のタイルなので、それより拡大すると粗くなります。
- 地図右下の📍ボタンで現在位置を出し、動きに合わせて追いかけます(もう一度押すと止める)。
- 現在位置はブラウザの決まりで **HTTPS で開いたとき(と `localhost`)だけ** 使えます。`http://192.168.x.x:8080/` や `http://<Tailscale の IP>:8080/` ではボタンが薄くなり、押すと理由が出ます。
- MiniPC で次を一度実行すると、Tailscale の中だけで使える HTTPS のアドレス `https://<MiniPC名>.<tailnet名>.ts.net/` ができます(インターネットには公開されません)。事前に Tailscale の管理画面 → DNS で MagicDNS と HTTPS Certificates を有効にしておきます。

  ```powershell
  tailscale serve --bg 8080
  ```

  止めるときは `tailscale serve reset`。iPhone では Safari の設定で位置情報を許可してください。

## 旅の記録(電車・飛行機など)

- iPhone の走行ロガーで「電車・飛行機・同乗・その他」を選んで記録した移動(生データの保存先の `trips\<走行ID>`)を、地図に別の線で出します。**国道などの制覇の判定には使いません**(見るだけ)。
- 地図右下の「旅」ボタンで表示を切り替えます。手段ごと(電車=緑・飛行機=紺・同乗=茶・その他=灰)にオン/オフでき、はじめは電車と飛行機だけ出します。設定はブラウザに覚えます。
- 線を押すと、日時(日本時間)・距離・かかった時間(飛行機は最高高度も)が出ます。GPS が3分より途切れた間は点線でつなぎます。精度が200mより悪い点(基地局での測位など)は使いません。
- サーバーの `GET /api/trips` が `location.csv` と `meta.json` を読み、線を間引いて返します(ファイルが変わるまで結果を使い回します)。MiniPC のサーバーで開いたときだけ見られます。
- ログタブの「年」で「期間を指定(旅行など)」を選び、日付を2つ入れると、その期間の **車のログと旅の記録をまとめて** 日ごと・時刻順に一覧にし、地図にも全部出します(車=赤紫、旅の記録は手段の色。この間は「旅」ボタンの設定にかかわらず期間の分だけを出します)。行や地図の線を押すとそのログの詳細を開き、電車などの行を押すとその線に寄ります。期間はブラウザに覚えます。
- 期間の下の欄に名前を入れて「この期間を保存」を押すと、旅行として MiniPC の `data/journeys.json` に保存され、どの端末からも「年」の欄の「保存した旅行」から選べます(名前の変更・削除もここで。ログ自体は消えません)。
- ログの一覧は、同じ日の中では走り始めた時刻の新しい順に並びます。時刻は `data/logs/meta.json` の `start` に入れます。前から保存してあるログは、ログタブを開いたときに読み込んで時刻を付けます(最初の1回だけ少し時間がかかります)。
- 保存した旅行を開いているときは、各行の × でそのログ・旅の記録を **旅行から外せます**(一覧の下の「この旅行から外したもの」にまとまり、↩ で戻せます。地図と合計からも外れます。ログ自体は消えません)。外したものは `data/journeys.json` の `exclude` に入ります。
- **地図に出すログの選び方**(2026-11-10 から): ログタブの一覧の各行の左のチェックで、そのログ(車・電車・飛行機など)を地図に出すかを決めます。期間を指定していないとき(「すべて」や年)は、はじめは何も出さず、チェックしたものだけを出します(一覧には電車・飛行機などの記録も日付順に並びます)。期間を指定しているときは、地図右下の「旅」パネルで選んだ手段(運転・電車・飛行機・同乗・その他。はじめは運転だけ)をまとめて出し、一覧のチェックで1本ずつ変えられます。チェックはこの端末だけに覚えます。ほかのタブ(国道など)では、ログの線は出しません。
- **移動手段を直す**(2026-11-12 から): iPhone のロガーで手段を間違えて記録したときは、ログタブで電車などの行を押して出る詳細(車のログは詳細の「移動手段」欄)で選び直します。iPhone のアプリのログ詳細からも直せます(サーバーに届いていればサーバーにも反映)。
  - MiniPC は走行フォルダの `meta.json` の `mode` を書き換え、車と車以外で `<走行ID>` ⇔ `trips\<走行ID>` にフォルダを移します。トンネルなどを補った位置は新しい手段で補い直します(飛行機などは補った位置を捨てます)。
  - **運転にする**と国道の判定に足します(地図のログがなければ `location.csv` から精度 50m 以内の点で GPX を作り、判定待ちにする)。**運転以外にする**と地図のログを `data/logs/removed` に移して制覇から外し、保存したログで判定し直します(MiniPC で判定できないときは画面で判定し直す確認が出ます)。運転に戻すと removed のログを戻します。
  - API: `GET /api/rawlog/mode?session=<走行ID>`(いまの手段)、`POST /api/rawlog/mode?session=<走行ID>&mode=car|ride|train|plane|other`。同じ走行の GPX が `/api/inbox` にもう一度届いても二重に保存せず、車以外にした走行の GPX は地図に入れません。
